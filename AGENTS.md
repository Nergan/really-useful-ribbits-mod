# Really Useful Ribbits — инструкции для AI-агентов

Аддон Ribbits для Minecraft 1.21.1, NeoForge и Fabric. У Ribbits есть обе сборки `4.1.6`. Диапазон зависимости в метаданных мода совпадает с версией внутри чужого jar: не `4.1.6`, а `1.21.1-NeoForge-4.1.6`. Книга Patchouli есть. Fabric-сборку не снимай.

## Опыт

Если по ходу задачи стало ясно то, что в следующий раз сэкономит неверный ход, допиши это в этот `AGENTS.md`. Ход работы и разовую ошибку не копируй. Неверную старую строку поправь, а не оставляй вторую рядом.

Слот сумки торговца на 256 считает `RibbitWorkData.slotCap`, сам `ItemStack` остаётся ванильным. Больше, чем стопка удерживает на деле, слот не берёт: Sengoku режет `setCount` до 99, и в сборке с ним слот торговца — 99, а стартовые 256 изумрудов ложатся в три слота. Компонент `max_stack_size` кодек сохраняет только до 99: стопка с 256 роняла сервер при первом сохранении риббита. Count больше 99 пишется рядом в `reallyusefulribbits_count`, а из сумки стопка уходит обычными стаками через `ContainerSupport.pieces`. Сумку проверяет стенд: призвать торговца на спавне, `data get entity @e[type=ribbits:ribbit,limit=1,sort=nearest] ReallyUsefulRibbitsWork.Items`, затем `save-all flush`. Пустые `{}` в слотах значат, что предметы при сохранении теряются.

Поиск блоков риббитом не вызывает `getBlockState` и `getFluidState`, пока `Level.isLoaded` ложен: ванильный `getBlockState` синхронно грузит чанк на серверном потоке. `BlockPos.findClosestMatch` по `FARM_CLAIM_RADIUS` 128 из `FarmerAi.perform` так держал тик десятки секунд, пока деревня ещё генерировалась (ModernFix watchdog: `isFarmBlock` → `allWorkBlocks` → `findClosest`). Скан идёт только по уже загруженным чанкам и по несколько колонок за вызов. `/locate ribbits:ribbit_village` — поиск структуры мода Ribbits, к этому аддону не относится.

Миксины — Kotlin. Сборка Fabric ставит `loom.mixin.useLegacyMixinAp = false`: Java-процессор refmap Kotlin не видит, а tiny-remapper переименовывает цели прямо в `remapJar`. После правки миксина проверь, что в классе из `fabric/build/libs` цель стала `method_…`. NeoForge работает на именах Mojang и refmap не нужен. Миксины на классы Ribbits — с `remap = false`.

Проклятия чародея переживают смерть. NeoForge переносит облик игрока `copyOnDeath()` вложения, Fabric — `ServerPlayerEvents.COPY_FROM`. Базовые значения атрибутов (размер, здоровье, гравитация VVVVVV) ванильный `restoreFrom` переносит сам, а эффекты — нет: их список лежит в `PlayerVisualData.curseEffects` и возвращается в `afterRespawn`. Там же гравитация снова смотрит вниз, иначе игрок возрождается и падает в небо. Эффект, снятый молоком, выпадает из списка при живом игроке. Снимает всё остальное только яблоко (`SorcererCurse.clear`).

Клиентские кулдауны считает свой счётчик `ClientSpells.ticks`. `LocalPlayer` пересоздаётся после смерти и смены измерения, и его `tickCount` с нуля на полминуты запирал переворот VVVVVV.

Серверный конфиг NeoForge 21.1 — `config/reallyusefulribbits-server.toml`, файл в `<мир>/serverconfig/` его только переопределяет. Старый TOML без `[sorcerer.spells]` с хаосом 25 правит `NeoForgeMod.migrateLegacyConfig` до загрузки конфигов.

Баллы заклинаний по умолчанию в сумме дают 9 999 092, 1 балл — 0,00001%. Дракон и гигантский варден по 1 баллу. Конфиг записывает все баллы, поэтому новая таблица по умолчанию сама в старые файлы не попадёт. `ServerSettingsText` сверяет файл с прежними таблицами (`POINTS_1_1_0`, `POINTS_1_1_2`): нетронутый файл получает новые баллы, правленый остаётся. Меняешь таблицу ещё раз — сверяй и с ней. Таблицы в README идут по убыванию баллов, шанс — баллы, делённые на сумму.

Торговец не создаёт сделку, где и плата, и товар — `minecraft:amethyst_shard`. Уже лежащая в `offers` такая сделка при тике становится 64 алмаза за 1 осколок. Осколки в стартовом запасе — валюта, не товар.

На Fabric экран настроек — Cloth Config через Mod Menu (`RibbitsConfigScreen`). Он правит тот же `reallyusefulribbits-server.properties` через `FabricRuntime.saveSettings`, и сервер в этом же процессе берёт значения сразу. Новый ключ настроек добавляй в экран вместе с файлом.

Задачи `runClient` и `runServer` без пути проекта запускают обе платформы сразу. NeoForge — `:runClient`, Fabric — `:fabric:runClient`.

Заклинания без клавиатуры проверяет одиночный мир с датапаком. Tick-функция зовёт `/reallyusefulribbits cast <ключ> @a[limit=1]`, перед каждым вызовом переносит риббита к игроку через `tp`, а `tellraw` выводит атрибуты в чат. Клиент пишет чат в `logs/latest.log`. С `pauseOnLostFocus:false` в `options.txt` мир без фокуса не встаёт на паузу.

Гигантский варден и кот больше ванильных потолков: `AttributeCapMixin` поднимает размер до 128 и здоровье до 1 000 000. У сущности шире 20 блоков `GiantEntityMixin` пропускает перебор жидкостей и блоков в хитбоксе, иначе варден ×100 перебирает миллионы блоков за тик. Варден ведётся без ИИ из `DeleteWorld`, `noPhysics` не сохраняется и ставится каждый тик.

В 1.21.1 из Super Secret Settings в игре остались только `invert`, `creeper`, `spider` и `blur`. Остальные эффекты — свои post-цепочки из ванильных программ (`bits`, `color_convolve`, `box_blur`) и своих `.fsh`. Программы лежат в пространстве `minecraft` с префиксом `rur_`: `EffectInstance` ищет программу там. `GameRenderer.loadEffect` в 1.21.1 приватный, его берёт `@Shadow`.

Рис в воде и куст на земле не стоят на пашне: фермой считается сам такой блок и земля под ним, иначе `nearestFarmOrigin` их не видит. Колючий куст — `SweetBerryBushBlock`, тег `reallyusefulribbits:prickly_bushes` и путь с `sweet_berry`, `prickly`, `thorny` или `bramble`. Рыбная клетка с коллизией выше 0.5 (верхний полублок в воде) — не `isOpenWater`: над ней воздух, но садиться туда нельзя.

## Правила

- Прежде чем писать своё, портировать или декомпилировать, найди готовый мод, порт или форк. Веб-поиск (Google, Perplexity) малоизвестные репозитории GitHub не видит: репозиторий без звёзд и без ссылки с уже проиндексированной страницы в их индекс не попадает. Ищи каталог GitHub. Перед поиском прочитай https://github.com/aaddrick/gh-cli-search/blob/main/skills/gh-search-repos/SKILL.md и для исходников https://github.com/aaddrick/gh-cli-search/blob/main/skills/gh-search-code/SKILL.md. Нижний порог звёзд не ставь: примеры `stars:>N` в скилле применяй только если владелец просил известные проекты. Скилл https://github.com/py-sit/github-search-skill отбрасывает репозитории без лицензии, без свежих коммитов и учебные, поэтому для порта и малоизвестного мода его не открывай. Сделай несколько запросов: `gh search repos` по имени, `--match readme` и `gh search code` по mod id; для порта добавь `--include-forks true` и список форков исходного репозитория. Дефис в имени совпадает со словами запроса. Минус в начале квалификатора — исключение: такой запрос отделяй `--`, в PowerShell ещё `gh --%`. Пустое описание, ноль звёзд и пустые topics результат не отменяют. Опубликованные моды дополнительно смотри в поиске Modrinth: исходник порта часто есть только на GitHub. Свою реализацию не начинай, пока этот поиск не сделан.
- Код — Kotlin. Новый Java-файл не добавляй. Уже лежащий Java переписывай на Kotlin, когда трогаешь этот мод, не меняя поведение.
- Имя jar: `<mod_id>-<loader>-<minecraft_version>-<mod_version>.jar`. В Prism и в чужую папку модов его не клади. Игрок качает GitHub Release, ту же сборку.
- Issues: чинить только дефект. На каждый issue ответить и закрыть, включая те, где правки нет.
- Коммит и пуш — только когда владелец прямо просит. Для пуша человек запускает `add-commit-push.cmd`. Теги `minecraft-*` двигает workflow релиза.
- Версии в `gradle.properties` не поднимай, пока задача этого не требует. Локальный путь к JDK туда не записывай.

Перед записью на CDN прочитай https://cdn.mikchan.net/ai/SKILL.md. Сначала `GET https://cdn.mikchan.net/version`. Токен не печатать и не выдумывать. Уже опубликованный номер версии не перезаписывается.

## Готово

Из каталога мода, по порядку. Сеть нужна. Собранный jar человеку для игры не отдавай.

1. Собери проект (`gradlew build --stacktrace`, либо `gradle build --stacktrace`, если wrapper нет).
2. Запусти клиент задачей Gradle и дождись главного меню, затем закрой окно.
3. Запусти локальный сервер и дождись готовности, затем останови его. Клиентский мод тоже не должен ронять сервер.
4. Если клиент или сервер упали, так и напиши. Сборка jar без запуска игры — не конец работы.

## Проверка мода и сборки

Работа над модом или сборкой заканчивается только после тестов, проверки запуском локального сервера и локального клиента. Сборка jar без этого не считается готовой.


## Modrinth

На Modrinth у каждой пары версии Minecraft и загрузчика одна версия: самая новая. Релиз снимает прежние версии этого слота и ставит на их место текущий jar.
